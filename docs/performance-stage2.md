# Второй этап: GameActor, сохранения, мобильный UI и выборочный Rust

База: `ad84c5969a12e47da538f38af322757f0e2f5f0d`, 18 октября 2026. Измерения после сделаны на рабочем дереве этого изменения; HEAD в JSON указывает базу до коммита. Все данные профилирования синтетические.

Сырые результаты: `performance/stage2/before.json`, `after.json`, `native-node.json`, `telegram.json`. Первый Node-замер сравнивает до/после оптимизации actor. В сравнении Telegram обе стороны **уже используют новую сериализацию**, меняется только SHA-256 backend. Складывать эти проценты нельзя.

В Telegram изолят фиксирует `Date.now`, а `performance` недоступен. Нулевые внутренние длительности не использованы: время берётся из `runFunction(...).time`, которое CLI переводит из секунд в миллисекунды. Пробы включают инициализацию кода/WASM, не читают БД, не записывают прогресс и не отправляют сообщения. Они не измеряют сетевую задержку кнопки и FPS телефона.

## GameActor: прежние байты, меньше повторной работы

`actorDigest` строит ту же последовательность байтов, что прежние `normalize → JSON.stringify`, включая порядок числовых ключей, Set, пустые поля, функции с метками callback, Unicode и округление чисел JSON. Хеш и формат сохранённых effects/timers не меняются.

Строки общих поддеревьев переиспользуются только во время одного синхронного чтения render. Кеш очищается до эффектов, перед setter и в finally. Между командами, запросами и render-проходами кеша нет. Setter продолжает сравнивать свежие значения до и после updater, включая изменения на месте. Тесты сверяют тысячи зависимостей с прежней реализацией и сохранённую совместимость таймеров.

## Выборочный Rust: только большие actor-отпечатки Telegram

Добавлена опциональная Cargo feature `actor-hash`, SHA-256 RustCrypto `sha2 = 0.10.9`, wasm-bindgen 0.2.129. Для hash-сборки используется opt-level 3; компактный боевой пилот собирается отдельно как прежде. Хеш-модуль — 25613 байт. Биндинги и бинарные байты встроены в серверную сборку; загрузки с внешнего URL во время запроса нет.

WASM применяется к actor-зависимостям размером от 4096 байт. Вход ограничен 4 MiB, остальные случаи используют прежний SHA-256 на JS. Инициализация ленивая, один раз на изолят. Проверяется известный NIST-вектор `abc`; ошибка инициализации, неверный digest или runtime trap отключает ускорение до конца этого изолята.

Проверки сравнивают SHA-256 с Node на границах блоков, больших состояниях, кириллице, emoji и непарных surrogate. Успешные пробы Telegram дополнительно подтверждают `hashMode: rust`, а не незаметный переход на fallback.

**Авторизация, HMAC, подписи Telegram, платёжные и экономические квитанции не используют этот адаптер.** Обычный Node GameActor остаётся на OpenSSL. В Node-симуляции native-shim первый WASM actor был медленнее (29.854 против 15.301 мс), хотя повторные восстановления ускорялись (9.105 против 12.191 мс). Включение обосновано измерением холодного полного сценария именно в целевом Telegram runtime.

Клиентский боевой WASM-пилот из первого этапа по-прежнему выключен. Урон, RNG, валюта, выдача предметов и квитанции остаются авторитетными серверными операциями. Rust на этом этапе меняет реализацию одного стандартного хеша, а не игровой баланс.

## Сохранения и SQL

- `meaningfulSave` больше не клонирует весь actor перед сравнением. Только отображаемый процент поездки нормализуется через копии веток; остальные данные читаются без изменений.
- Уже подготовленный и проверенный снимок используется для записи, не строится повторно. Из `frame` возвращается уже заблокированный актуальный инвентарь, без лишнего SELECT.
- Команда, не изменившая инвентарь/экипировку, не переписывает все предметы и не запускает лишнее восстановление actor после такой записи.
- Если инвентарь изменился, остаются проверка исходных строк, количество/уникальность, ledger IDs, освобождение слотов, remap и повторное чтение канонических предметов.
- Все изменения и квитанция остаются в прежней транзакции/атомарном CAS. Схема, player locks, expectedVersion, sessionGeneration и resetVersion не меняются. Отказ команды и повтор её operation ID проверяются существующими тестами.

Необязательный браузерный display cache сериализуется в idle callback или через короткий timer fallback. Несколько версий объединяются до последней, одинаковые версии не записываются повторно, устаревшая задача отменяется при новой версии/сбросе/unmount. Кеш v2 использует существующий компактный формат проекции, избегая дублирования player/quests между save и game. Ошибка или отсутствие планировщика/места в storage не отменяют подтверждённый результат.

**Журнал незавершённой операции записывается синхронно перед отправкой запроса.** Его формат, токен исходной сессии и operation ID не изменились. Display cache не используется для восстановления прогресса, начислений или замены серверного персонажа. Резервные копии localStorage и PostgreSQL не удаляются.

## Мобильный интерфейс

Новые серверные версии переиспользуют неизменившиеся JSON-ветки инвентаря, экипировки, заданий и других частей проекции. Это сохраняет зависимости useMemo и props карточек. Сброс или другой владелец не переиспользует старый прогресс. Реальные изменения предмета/блокировки/класса и языка остаются видимыми.

Оба интерфейса инвентаря сортируют заранее вычисленные оценки. Порядок «надето первым», оценка с учётом класса/заточки и стабильность равных элементов сохранены; в тесте на 500 предметов оценка вычисляется 500 раз. Карточки вынесены в React.memo с прежней разметкой и стилями. Fantasy-beta использует тот же компонент с собственным style-prop. Пагинация, задержка игровых команд, скрытие предметов и изменение дизайна не добавлялись.

Реальные карточки проверены на 200 предметах, обновлениях кошелька, изменении блокировки и выборе предмета. Production-проверка запускает эмитированные модули всех трёх оформлений и навигацию/восстановление сохранений. Физические Android/iOS, память WebView, плавность прокрутки, тепловое ограничение CPU и FPS не измерены; эти результаты не подменяются DOM-тестами.

Стартовый JS: 826660 → 828964 байт, gzip 198761 → 199418 байт. Это +2304 raw / +657 gzip за структурное переиспользование и планировщик; весь WASM остаётся на сервере. Размер серверного модуля 820606 байт, ниже лимита 1 MiB. Rust добавляет линейную память WASM; расход RAM на телефоне и серверный peak RSS не объявляются измеренными этим отчётом.

## Проверки, сборка, откат

Локально прошли 348 JS/TS тестов, отдельные целевые UI-проверки после финальных изменений, два нативных Rust-теста, typecheck, production build, native release audit и проверка трёх production-интерфейсов. CI также пересобирает Rust из исходников и проверяет SHA/fallback. Проверки HTTP/SQL выполняются без ограничений sandbox на локальные порты.

```sh
npm run wasm:build
npm run wasm:test
npm run perf:actor -- .migration-backups/native-comparison.json
node scripts/benchmark-telegram-actor.mjs .migration-backups/telegram-comparison.json
npm run build:telegram
npm test
npm run serverless:audit
node --experimental-vm-modules scripts/interface-production-check.mjs
```

`benchmark-telegram-actor.mjs` использует официальный CLI credential resolver и только синтетический `/run`; требует предварительного `perf:actor`. Он не публикует диагностический endpoint. Доступ к `.tgcloud` вручную не нужен.

Чтобы отключить Rust без изменения данных, собрать с `ACTOR_WASM=0` и опубликовать обычным способом. Результат SHA-256 идентичен, так что переписывать effects, таймеры, сохранения и квитанции не требуется. Для полного отката кода подходит предыдущая сборка, без отката БД. Render-сервер не возвращается.

Реализация SHA-256 опирается на [RustCrypto sha2](https://docs.rs/sha2/0.10.9/sha2/); утверждения об ускорении основаны на замерах этого проекта, не на общем обещании производительности Rust.
