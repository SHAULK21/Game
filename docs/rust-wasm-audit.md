# Аудит производительности и пилот Rust/WASM

Дата: 18 октября 2026. База сравнения: `20ee3fae45959abf54e8d15b6d497bcc4ba6c486`.
Это результат аудита, пилота и оптимизации загрузки. Массовая миграция механик не выполняется: измерения не подтвердили пользу переноса отдельных формул в игровой запрос.

## Архитектура и источник задержек

- `ServerGameProvider` получает подтверждённую проекцию через официальный `Telegram.WebApp.Serverless.call`. Клиент посылает команды; `GameStore`, серверный actor и атомарный документ определяют результат, награды и сохранение.
- Общие правила находятся в `GameContext.tsx` и `utils/`, серверная сборка извлекает их через `actorEntry` и `build-game-engine.mjs`. `GameActor` восстанавливает состояние, вычисляет зависимости эффектов, выполняет действие и сериализует результат.
- UI импортировал React-контекст из того же файла, что и локальный движок. Его правила и каталоги загружались даже при выборе серверного провайдера. Теперь подписка UI находится в лёгком `GameStateContext.ts`, а локальный провайдер загружается динамически только вне Telegram.
- Все три интерфейса уже имели динамические entry и разделы. Сохранён выбор только одного оформления. Проверка графа сборки запрещает возвращать локальную симуляцию в Telegram startup и выбранный интерфейс.
- CPU-профиль синтетического восстановления actor показывает значительную работу в нормализации зависимостей, `digest` и хешировании, а не в формулах урона. Менять формат отпечатков эффектов без отдельного анализа сохранённых таймеров опасно; это отдельное направление оптимизации.
- `locale` остаётся крупным общим модулем (~560 KB raw). Следующий кандидат — отложенный словарь украинского языка с сохранением синхронных контрактов перевода. Он не менялся этим выпуском.
- Чтение частной копии production-документа: 817021 байт, один замер чтения 39 мс, готовая проекция 0 мс по грубому `Date.now`. Это не замер боя, записи или задержки кнопки на телефоне. Записи, передачи сессии и отправки сообщений проба не выполняет.

## Изменения загрузки и UI

- Контекст подписки выделен из локальной симуляции. Существующие импорты серверного actor и локальные сохранения совместимы через прежние экспорты.
- Изменение транспортного статуса больше не создаёт новую игровую проекцию. Компоненты, использующие статус сессии, подписываются на него через `useSyncExternalStore`; подтверждённые игровые изменения обновляют UI как прежде. Тест проверяет отсутствие игрового рендера на `saving` и обновление после квитанции.
- Статические `/assets/*` кешируются на час; HTML остаётся `no-store`. Telegram принимает маску только с завершающим `/*`, поэтому отдельная маска `*.js` не поддерживается. Годовой immutable-кеш не назначается всему каталогу: среди изображений есть имена без версии. Пути существующих сохранённых картинок не меняются.
- Удалены неиспользуемые `@google/genai` и `motion`. Они уже исключались tree shaking; удаление уменьшает установку зависимостей, а не объясняет сокращение браузерного бандла.
- Изображения текущего UI уже используют WebP, включая версии текстур с хешами. В public остаются исходные PNG размером 2–3 MB; CSS обращается к оптимизированным WebP. Каталог public (~61.8 MB, 287 файлов) не равен объёму первоначальной загрузки. Исходники не удалялись вслепую.

Размеры сравниваются по одному алгоритму обхода **статических** импортов Vite manifest. Они исключают последующие экраны, картинки и внешний Telegram SDK. Размер gzip — сумма gzip отдельных файлов, а не измерение фактического Content-Encoding сервера. Цель бюджета startup — менее 900000 байт JS.

| Telegram startup | До | После |
|---|---:|---:|
| JavaScript raw | 1133515 B | 826660 B (−27.1%) |
| JavaScript gzip | 291061 B | 198761 B (−31.7%) |

Это уменьшение объёма кода, а не обещание ускорения всей игры на тот же процент.

## Приоритеты после профилирования

| Модуль | Решение |
|---|---|
| Бой | Пилот чистого типизированного урона. Полные раунды, крит, эффекты и RNG остаются в действующей реализации: формулы слишком малы для выгоды от отдельного вызова WASM. |
| Предметы/экипировка | Оставить TS: один расчёт занимает меньше микросекунды; перенос строк, объектов и таблиц добавит стоимость. |
| Уровни/награды | Оставить авторитетную реализацию TS; расчёт уровня не является узким местом. |
| Инвентарь | 500 предметов фильтруются за ~37 мкс. Сначала профилировать рендер большого списка, перенос фильтра не оправдан. |
| Экспедиции/профессии/экономика | Сохранить серверные расчёты. Тесты проверяют текущие механики; отдельное CPU-узкое место не установлено. |
| React/Telegram API | Оставить TS, устранить лишние импорты и рендеры. |
| Actor/атомарный документ | Следующий серверный приоритет: зависимости, сериализация и размер документа. Это не доказанная задача для переноса математических формул. |

## Rust-пилот

`engine/` — отдельная библиотека Rust stable 1.99.1, target `wasm32-unknown-unknown`, `wasm-bindgen` 0.2.129 с Cargo.lock. Только `combat.rs` и ABI; пустых модулей остальных механик нет.

Перенесён ограниченный чистый расчёт урона: physical / elemental / true, физическая и магическая защита, пробивание, пределы сопротивления, множители и порядок округления. Эталон выделен без смены формулы в `utils/typedDamage.ts`; он же продолжает работать на сервере. Это **не перенос всего боевого раунда**.

ABI v1 принимает пакет чисел `Float64Array` (8 значений на удар), без JSON и переходов на каждом арифметическом действии. Пакет ограничен 4096 ударами; проверяются NaN, Infinity, диапазоны и безопасные целочисленные результаты. Случайные события генерируются прежним сервером, Rust не назначает награды. Нет Telegram ID, хранилища, сети, валюты или API сохранений внутри Rust.

`createCombatCalculator` — опциональный async-адаптер, по умолчанию выключен. Биндинги загружаются динамически при первом обращении. Ошибка загрузки, timeout, несовместимый протокол или некорректный результат переводят его на TS. Повторная инициализация не зацикливается; входы фиксируются до await. Производственный граф не включает этот пилот.

20 000 входов с фиксированным seed сравниваются с TS точно, без epsilon. Есть golden-тесты, границы сопротивлений, половинное округление, неправильные размеры, переполнение, отказ загрузчика и Vite-сборка с отдельным динамическим чанком.

### Результат пилота

WASM: 17360 B raw / 7891 B gzip; одна локальная инициализация ~24 мс. Линейная память 1.06 → 1.44 MiB после прогона, включая пакет 4096. Исходные данные: `docs/performance/wasm.json`.

| Ударов в пакете | TS, мкс | WASM, готовые числа, мкс | WASM с полным адаптером, мкс |
|---|---:|---:|---:|
| 1 | 0.469 | 0.596 | 1.934 |
| 32 | 5.010 | 1.948 | 9.113 |
| 512 | 64.259 | 14.511 | 136.101 |
| 4096 | 604.070 | 128.745 | 951.955 |

Подготовленные числовые пакеты показывают ускорение цикла, но полноценный путь с упаковкой, копированием и валидацией медленнее TS. Даже пакет 4096 не оправдывает включение адаптера. Решение: **не включать WASM в обычную игру**. Подход можно повторно оценить для будущей массовой симуляции, если данные изначально хранятся числовыми массивами.

Отдельная read-only проба в Telegram V8 подтвердила наличие `WebAssembly` и компиляцию минимального WASM-модуля. Это не тест биндингов Rust внутри backend и не доказательство выигрыша такого backend. Критическая реализация остаётся серверной TS.

## Сборка и проверки

Обычный выпуск не требует Rust: проверенные JS/WASM-артефакты пилота хранятся в репозитории и не входят в production-граф. Изменение Rust требует пересборки. `engine/target` и локальные toolchain игнорируются Git.

```sh
rustup toolchain install 1.99.1 --profile minimal --target wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked
npm run wasm:build
npm run wasm:test
npm run perf:wasm -- docs/performance/wasm.json
npm run build:telegram
node --cpu-prof --cpu-prof-dir=.migration-backups --import tsx scripts/profile-game.ts .migration-backups/performance.json
npm test
npm run serverless:audit
node --experimental-vm-modules scripts/interface-production-check.mjs
```

CI отдельно собирает Rust из исходников, запускает native unit test, сравнение с TS, fallback и benchmark artifact. Предсобранный wasm-bindgen проверяется SHA256. Основной CI проверяет TS, игровые тесты, сборку и запрет нежелательных модулей. Параметры `CARGO_BIN`/`WASM_BINDGEN_BIN` позволяют использовать изолированные локальные инструменты.

## Совместимость, выпуск и пределы проверки

Форматы actor/save и ABI команд, проверенный Telegram ID, правила сессий, версии, reset epoch и точный журнал operation ID сохранены. Данные production не мигрируются повторно. Сервер не принимает результаты клиентского WASM; существующие проверки экономики, повторов, рынка, сохранений и переключений устройств остаются обязательными.

Пилот откатывается использованием TS-адаптера по умолчанию. Оптимизация загрузки откатывается предыдущей сборкой/коммитом без отката базы. Не требуется возвращать Render-сервер.

Автоматизированная DOM-проверка запускает эмитированные production-модули трёх оформлений, навигацию и восстановление сохранения. **Физические Android/iOS/Telegram Desktop, FPS, long tasks и холодная загрузка на одинаковой мобильной сети не измерены.** Для будущего включения WASM обязательны эти проверки и выигрыш полного пути, а не только внутреннего Rust-цикла. Полная миграция и мобильная приёмка WASM не объявляются завершёнными этим отчётом.
