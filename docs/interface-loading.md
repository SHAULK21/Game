# Загрузка интерфейсов

Режим фиксируется на время жизни документа. Ключ `aethelgard_interface_style`
сохранён; отсутствующее, некорректное или недоступное значение означает `modern`.
`main.tsx` подключает только общие стили, Telegram и общие провайдеры.
`InterfaceLoader` импортирует одну из трёх точек входа вместе с её CSS.
Нейтральный локализованный экран загрузки не использует оформление игры.
Ошибка импорта показывает повтор через перезагрузку документа (так сбрасывается
кэш отклонённого динамического импорта).

Общая игровая логика вынесена в `GameScreens`. Fantasy-режимы разделяют маршруты,
регистрацию и действительно используемые обоими режимами игровые компоненты
и ресурсы. Классические header/navigation, beta header/navigation/book,
панели охоты и классический рендерер hero-codex загружаются отдельно.
Мобильные правила разделены на общую геометрию и CSS выбранного режима.
Tailwind utilities остаются общими: они используются общими игровыми экранами.

## Переключение

Перед проверкой блокировок выполняется принудительная фиксация ожидающих React
обновлений. Затем прогресс записывается и проверяется чтением из localStorage,
сохраняется черновик регистрации, записывается и проверяется настройка, и только
после этого вызывается reload. Активный режим ничего не делает. Ошибка хранения
отменяет переключение. Сохраняются раздел, игровые данные и черновик регистрации;
данные навигации привязаны к аккаунту и версии сброса.

Незавершённый бой, путешествие, несовпадающий аккаунт/версия сброса и выполняющиеся
операции предметов/валюты блокируют переключение с локализованным пояснением.
Счётчик операций охватывает запрос и последующее обновление инвентаря, а также
ожидание premium invoice. Проверка выполняется и внутри метода переключения,
поэтому обход disabled-кнопки не пропускает защиту.

## Проверки

- `npm run lint`: TypeScript, успешно.
- `node --import tsx --test --test-concurrency=2 tests/*.test.ts`: 201/201 успешно.
- `npm run build`: production-сборка, успешно.
- `npm run check:interfaces`: production-сборка и выполнение настоящих выходных
  ESM в эмулированном документе, успешно. Три холодных старта, отсутствие чужих
  entry/CSS/dashboard, открытие всех разделов, шесть направлений переключения,
  сохранение персонажа, отсутствие ошибок выполнения.
- Новые тесты: неверная/отсутствующая настройка, выбор активного режима,
  сохранение актуального состояния при покупке и переключении в одном обработчике,
  блокировки боя/путешествия/операции до завершения обновления инвентаря,
  отказ localStorage, сброс аккаунта, ошибка выбранного импорта и локализованный повтор.

## Ограничения

Production-проверка использует Node VM + JSDOM, подставленные API и новый документ
для reload. Она не измеряет настоящий браузерный Network, декодирование изображений,
paint, мигание оформления, мобильный viewport или живой Telegram SDK.
Chromium не удалось установить (загрузка возвращала неполный архив); доступный
браузер не открывал локальный сервер. Эти браузерные проверки остаются необходимыми
на доступном production/staging-адресе. Само приложение не требует VM/JSDOM.
Общий JS остаётся крупным; дополнительные разбиения игровой логики не входили в
эту задачу. Общие картинки предметов, используемые обоими fantasy-режимами,
намеренно остаются общими.
