# Перегортання сторінок бестіарію — завдання для Codex

## Мета й обсяг

Реалізувати перехід «список істот → досьє істоти → назад» як перегортання листа книги у пергаментному інтерфейсі. Цей документ задає вимоги для окремого PR з реалізацією; сам по собі анімацію не додає.

Зберегти поточне оформлення, розміри блоків, локалізацію та поведінку гри. Верхній HUD, нижня навігація, зовнішній фон, корінець і зовнішня рамка залишаються нерухомими. Портрет, текст, характеристики, здобич та іконки рухаються разом з листом. Не застосовувати ефект до modern UI або до всіх FolioPage автоматично.

## Перед змінами

1. Прочитати наявні правила проєкту та знайти фактичний екран списку/досьє і власника його стану.
2. Відправна точка для пошуку компонентів: src/interfaces/fantasy/components/ui/BestiaryUI.tsx. Це набір спільних компонентів, а не гарантований власник навігації.
3. Знайти чинний пергаментний режим та його CSS/асети. Не підміняти його іншим варіантом інтерфейсу.
4. Якщо список і досьє ще не є окремими станами або корінець неможливо відокремити наявними ресурсами, описати конкретну проблему й узгодити її з автором перед розширенням обсягу. Не вигадувати нові екрани чи перемальовувати дизайн.

## Асети

Нові графічні асети для CSS 3D прототипу не обов'язкові. Використати існуючий матеріал пергаменту для обох сторін листа. Тіні та блік зробити CSS-градієнтами.

У репозиторії є public/assets/sprites/generated/ui/bestiary-reference/book-page-with-spine.png. Назва вказує на можливе поєднання листа й корінця: перевірити зображення перед використанням. Не обертати всю текстуру, якщо вона містить нерухомий корінець. Спочатку використати наявні окремі шари або перевірене кадрування; якщо потрібен окремий арт — запросити його в автора. Не домальовувати корінець навмання.

Опціонально: page_turn_01.ogg, 0.3–0.6 с, негучний шелест. Відсутність звуку не блокує реалізацію. Якщо звук надано, підключити до існуючих налаштувань гучності й мобільного розблокування аудіо, без автозапуску до взаємодії.

## Геометрія та шари

- Стабільний контейнер сторінки з perspective приблизно 1200–1600 px.
- Нерухома цільова/поточна сторінка під рухомим листом; поверх — рухомий лист із front/back, тінню та бликом.
- Для листа: transform-origin: left center; transform-style: preserve-3d.
- Для кожної сторони листа: backface-visibility: hidden; задня сторона повернута на 180°.
- Контент звороту не має бути дзеркальним текстом передньої сторони: використати пергамент без тексту.
- Обмежити ефект областю книги, зберегти HUD видимим. Перевірити overflow, stacking contexts і можливе flattening CSS 3D; не навішувати обрізання/opacity на preserve-3d вузол без перевірки.
- Висота контейнера не стрибає під час переходу. Анімується видима область аркуша, без створення величезного GPU-шару на всю довжину прокручуваного списку.

### Вперед

Рухомий поточний лист повертається від 0° до приблизно -180° навколо лівого корінця; досьє вже під ним. Аркуш відходить справа наліво. Після завершення залишити тільки активне досьє.

### Назад

Відтворити попередній рух у зворотному часі навколо того самого лівого корінця: лист зі списком повертається від -180° до 0° поверх досьє. Видимий рух зліва направо. Не переносити корінець на правий край через зміну transform-origin: це виглядає як інша книга.

CSS rotateY створює плоский лист; градієнт лише імітує згин. Не називати це справжнім page curl. WebGL, shader і нову бібліотеку не додавати на першому етапі.

## Тривалість і світло

- Автоматичне перегортання: 350–450 мс, початкове значення 400 мс.
- Easing: cubic-bezier(0.4, 0.1, 0.2, 1).
- Широка м'яка тінь на нерухомому листі та вузький блік на рухомому.
- Інтенсивність залежить від progress: майже нуль на краях, максимум біля середини, наприклад sin(PI * progress).
- Градієнт темний → світлий → темний має підкреслювати освітлення паперу, без товстої чорної смуги.
- Анімувати transform/opacity. Не рухати layout через width/height/top/left і не знімати DOM-скриншоти кожного кадру.
- will-change застосовувати лише під час взаємодії та прибирати після неї.

## Стан, навігація і життєвий цикл

Єдиний контролер переходу: idle → dragging/animating → idle. Зберігати from, to, direction, progress та ідентифікатор переходу. Не монтувати більше двох змістових сторінок; зворот листа — декоративний.

Підготувати цільову сторінку та потрібні зображення до запуску. Не показувати порожній лист під час завантаження. Не запускати запити/бойові дії двічі через одночасний монтаж двох сторінок.

Під час автоматичного руху заблокувати повторні переходи всередині книги та взаємодію з неактивними сторінками. Не блокувати весь застосунок. Вихід через нижню навігацію скасовує перехід і прибирає тимчасові шари.

Завершувати перехід один раз. Фільтрувати transitionend за target/propertyName; передбачити завершення, якщо подія не прийшла, а також cleanup при unmount, зміні розміру, pointercancel і втраті pointer capture. Після скасування жоден старий callback не має змінювати новий екран.

Зберегти семантику наявної навігації. Якщо використовується history/router, записувати один перехід вперед; повернення не додає новий запис. Browser Back узгодити з тим самим контролером. Якщо навігація локальна — не вводити новий router заради ефекту.

Зберігати scroll position списку й відновлювати її після повернення; нове досьє відкривати з початку. Після завершення переміщати фокус на заголовок досьє, а після Back — на вибрану істоту, без стрибка прокрутки. Приховані сторінки виключити з accessibility tree і tab-навігації (inert/aria-hidden з коректним управлінням фокусом).

## Tap і свайп

Tap/клавіатура на доступній істоті запускають перегортання вперед. Кнопка «Назад» запускає зворотне. Заблокована істота зберігає наявну поведінку.

Свайп додати після стабільної tap-версії, у межах наступного PR з реалізацією:

- Pointer Events і touch-action: pan-y; зберегти вертикальний скрол.
- Приймати горизонтальний жест після приблизно 10 px, коли abs(dx) > 1.3 * abs(dy).
- Не перехоплювати жести на кнопках, посиланнях, полях та вкладених горизонтальних списках.
- Після захоплення жесту використовувати pointer capture; progress обмежувати [0, 1].
- Рух листа слідує пальцю без easing. rotation = -180 * progress для руху вперед; для повернення interpolate(-180, 0, progress).
- progress >= 0.35 завершує перехід; менше — повертає початковий стан. Догортання плавне, з тривалістю відповідно до залишку руху.
- Скасований drag не змінює вибір, route/history чи scroll. Після розпізнаного drag придушити синтетичний click.
- У досьє свайп вправо означає Back. У списку свайп вліво відкриває тільки явно вибрану доступну істоту; за відсутності вибору не вгадувати ціль. Tap залишається основним способом відкрити істоту.

## Доступність і fallback

prefers-reduced-motion: reduce — короткий fade 100–150 мс без повороту і звуку. Якщо налаштування змінюється під час переходу, безпечно завершити його. За відсутності працездатного CSS 3D застосувати той самий fallback.

Не додавати bounce, elastic, zoom, glow, particles чи окремі рухи тексту/портрета.

## Послідовність реалізації

1. Знайти конкретну пергаментну сторінку, відокремити нерухому оболонку без зміни вигляду.
2. Додати контролер і CSS 3D перехід по tap та Back, тінь, cleanup, reduced motion.
3. Перевірити результат, потім додати свайп і відновлення скролу/фокуса.
4. Виконати наявні перевірки, доречні до змін. Нові тести — лише на істотну логіку: один commit навігації, скасування drag, повторний input і cleanup. Не писати тести, що просто звіряють рядки CSS.
5. У PR з реалізацією вказати змінені файли, результати перевірок і фактично перевірені браузери. Не заявляти перевірку Android/iPhone без доступного пристрою чи відповідного браузера.

## Критерії приймання реалізації

- [ ] Tap на «Лютий лісовий вовк» відкриває досьє за приблизно 400 мс; усі елементи досьє збережені.
- [ ] HUD, нижня навігація, корінець і фон нерухомі.
- [ ] Back має зворотний рух із тим самим лівим корінцем.
- [ ] Наступний лист готовий під поточним; немає дзеркального тексту, мерехтіння, стрибка висоти чи обрізаного портрета.
- [ ] Тінь/блік плавно посилюються і зникають.
- [ ] Повторні tap не створюють подвійної навігації або зайвих сторінок.
- [ ] Вертикальний скрол, дії в досьє й нижня навігація працюють; вихід під час руху безпечний.
- [ ] Свайп завершується/скасовується за порогом; pointercancel і resize не залишають блокування.
- [ ] Список відновлює скрол і фокус; прихований контент недоступний для взаємодії.
- [ ] Reduced motion і fallback працюють.
- [ ] Перевірено desktop, Android Chrome та iOS Safari, або чітко зазначено, які перевірки недоступні.
- [ ] Modern UI, баланс, енергія, збереження й бойова логіка не змінені.
