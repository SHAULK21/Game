# Экспедиции: серверная основа, не завершённый выпуск

Дата: 15 октября 2026. Спецификация: [expeditions-spec.md](expeditions-spec.md).

**Полное ТЗ не выполнено. Новая система не включена в игровом интерфейсе.**
Платные операции не опубликованы как HTTP-маршруты. Нельзя считать наличие
серверного модуля готовой игровой механикой или завершённым переносом прогресса.

## Почему нельзя включить обучение и награды в текущем main

`GameContext` по-прежнему сохраняет основного персонажа, золото и часть предметов
локально. `owned_items` обслуживает серверные предметы; кошелёк `market_gold`
остаётся отдельным торговым кошельком. Это ещё не единый серверный кошелёк героя.
PR #88 не объединялся: его проверка структуры checkpoint не подтверждает
происхождение золота, предметов и результатов игровых действий.

Спецификация прямо требует серверного владения золотом и предметами **до выпуска**
платного обучения и выдачи. Новый модуль проверяет `character_authority =
'server-actions-v1'`. Миграция оставляет всем существующим и новым строкам
`legacy-local`. В этой реализации нет API или настройки окружения, повышающих
эту отметку. Простое выставление отметки вручную не заменяет необходимую работу.

## Что реализовано

- Единый каталог из существующей таблицы экспедиций. Перенос таблицы в общий
  модуль не меняет действующую локальную добычу.
- Версия баланса, три маршрута, четыре цели, длительности 1/3/7 часов,
  подготовка, отдельный навык 1–20 и точная цена `500 × L²`.
- Нормализованный прогноз, сохранённый случайный результат, бонусное событие,
  коэффициент бригады 0,65 без обязательной выдачи редкого предмета.
- Транзакционный `ExpeditionStore`: блокировка строки владельца,
  `expectedVersion`, проверка поколения и токена активной сессии, reset epoch,
  проверка повторного operationId и параметров, актуальное состояние при повторе.
- Склад с частичным получением и непосредственной передачей в `owned_items`.
  В JSON-сумке вторую копию хранить запрещено. При заполненной сумке остаток
  остаётся на складе; герой освобождается; новый запуск требует разобрать склад.
- Размер торгового лота остаётся 999. Ресурсный стак в SQL допускает положительное
  значение до предела INTEGER 2 147 483 647. При достижении этого предела используется
  свободный дополнительный слот либо сохраняется остаток на складе. Обрезки нет.
- Досрочное возвращение без бонусного события, полное завершение по серверному
  сроку даже при нажатии старой кнопки возврата, опыт/статистика один раз,
  последние 20 отчётов.
- Общий слух по Europe/Kyiv; заказ с зафиксированной нейтральной ценой ×1,25,
  действительным расходом незаблокированных серверных предметов и дневным лимитом.
- Базовая Premium-формула без платного навыка; единая временная отметка,
  приостановка на время отправления/занятого склада; явная настройка повторной
  платной бригады. Повтор не списывает деньги при неполученной добыче, нехватке
  золота или окончании подписки.
- Внутренняя миграция уже проверенного серверного сохранения: резервная копия,
  legacy-отправление с исходными сроками/добычей/старыми правилами частичного
  выхода. Нет отдельного приёма локальных наград из HTTP-запроса.
- Административный сброс очищает состояние, операции, канонический снимок и сессию.
  Архивные резервные копии остаются в старой версии сброса и не используются как
  игровое состояние. Уведомления используют существующую очередь и настройки.

## Проверки

Проверки вызывают непосредственно `ExpeditionStore` и выполняют настоящие SQL
транзакции. Локальный путь — PostgreSQL WASM (PGlite); при `TEST_DATABASE_URL` тот
же набор работает через `pg.Pool` с отдельными соединениями и изолированной схемой.
GitHub Build настроен на PostgreSQL 16. Локальную проверку PGlite нельзя выдавать
за выполненный запуск внешнего PostgreSQL-сервера.

| Сценарий | Проверка модуля |
| --- | --- |
| Локальный кошелёк пытается купить навык | Отказ без изменения баланса/реестра |
| Обучение, нехватка золота, максимум | Точная цена/один уровень либо атомарный отказ |
| Два параллельных старта | Один запуск, второй получает конфликт версии |
| Потерянный ответ, повтор после нового прогресса | Одна награда/плата, возвращена актуальная версия |
| Другая сессия/владелец/resetVersion | Старый запрос отклонён |
| Полная сумка при возвращении | Склад сохранён, герой освобождён, ресурсы не восполнены |
| 998/999/1000/1 000 000 единиц | Точное количество при сохранении и выдаче |
| Предел INTEGER | Остаток на складе либо дополнительный свободный слот |
| Ошибка БД при записи квитанции | Выдача откатывается; повтор с тем же ID безопасен |
| Обучение во время бригады | Активный снимок не меняется |
| Заказ после полуночи | Старая цена сохраняется, материалы реально списываются |
| Premium без навыка 5 | Базовая добыча сохраняется |
| Склад не разобран/нет золота/Premium истёк | Автоматическая бригада не списывает новую плату |
| Legacy и административный сброс | Одна миграция, исходная добыча, старый запрос не восстанавливает сброс |

## Что остаётся до выполнения ТЗ

1. Закончить канонический сервис персонажа: все источники и расходы золота,
   создание/расход/экипировка предметов через конечные серверные игровые операции;
   одноразовый выбор локального персонажа без постоянного snapshot-upload API.
2. Подключить HTTP-операции к проверенному initData, получение/явный перенос
   активной сессии, монотонное применение ответов, журнал неизвестных результатов
   и статус сети в настоящем клиенте. Ответ персонажа должен проецировать
   `owned_items` обратно в сумку; внутренний канонический JSON намеренно пуст.
3. Переключить старую экспедицию и Premium на серверный путь без параллельной
   локальной выдачи. До этого действующие обработчики main сохранены.
4. Добавить самостоятельный экран, карточку поселения, переход из шахты,
   отображение навыка в профессиях, слухи/заказы в таверне, RU/UK.
5. Связать личное отправление со всеми обработчиками физического присутствия.
   Локальные обработчики сейчас не знают о состоянии нового серверного модуля.
6. Провести проверки двух настоящих клиентских сессий, сети/перезагрузки/сна,
   выбора миграции и визуальные проверки трёх оформлений на 320/390/430 px.

**Ни визуальное соответствие, ни полный пользовательский сценарий экспедиций
этим изменением не подтверждены. PR #88 остаётся черновиком.**
